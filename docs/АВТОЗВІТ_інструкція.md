# Автозвіти: як налаштувати й як це працює

**Принцип.** У програмі (Звіти → «Автоматичні звіти») зберігається лише розклад: який звіт, коли, кому. Листи надсилає окремий скрипт `autoreport/send.mjs`, який безкоштовно запускає GitHub кожні 30 хвилин (`.github/workflows/autoreport.yml`). Він читає розклад із бази, рахує звіт за період, формує лист із таблицею й файлом Excel та надсилає через Gmail.

## 1. Що саме надсилається
- Звіти: По пацієнтах, По лаборантах, По лікарях, По скеруваннях, За розподілом, По оплаті, По пільгах, По послугах. «Конструктор» і «Управлінський» — лише вручну.
- Період за правилом: **щодня** — за вчора; **щотижня** — за попередній тиждень Пн–Нд; **щомісяця** — за попередній місяць.
- У листі таблиця «група → послуг, візитів, пацієнтів, сума» + «Разом»; «По оплаті» додає оплачено/безготівка/готівка/неоплачено. Це **спрощена версія** екранного звіту (без графіків і детальних колонок). Прізвища пацієнтів у лист не потрапляють.
- Час — за Києвом. Лист надсилається раз на добу, щойно настав призначений час (затримка запуску GitHub до кількох хвилин — нормальна).
- Програмні автозвіти («Щоденний по оплаті» 08:30, «Місячний по пацієнтах» 1-го о 09:00) створюються при першому відкритті блоку **вимкненими**: спершу вкажіть одержувача й увімкніть.

## 2. Одноразове налаштування (робите ви; секрети я не бачу)
1. **Пароль застосунку Gmail.** В акаунті Google (той, що власник проєкту Firebase): Безпека → увімкнути двоетапну перевірку → «Паролі застосунків» → назва `CTMRI` → скопіювати 16 символів.
2. **Сервісний акаунт Firebase.** Firebase Console → ⚙ Налаштування проєкту → Облікові записи служби → «Створити новий закритий ключ» → завантажиться файл `.json`. Його вміст не публікувати й не пересилати.
3. **Секрети GitHub.** Репозиторій `ctmri` → Settings → Secrets and variables → Actions → New repository secret. Три секрети:
   - `FIREBASE_SERVICE_ACCOUNT` — **весь вміст** файлу `.json`;
   - `SMTP_USER` — адреса Gmail;
   - `SMTP_PASS` — пароль застосунку.
4. Після додавання файл `.json` з комп'ютера видалити.

## 3. Перший запуск і перевірка
1. Репозиторій → Actions → «Автозвіти» → Run workflow, лишити «пробний запуск» увімкненим: лист **не** надсилається, у журналі видно, що було б надіслано.
2. У програмі створіть тестовий автозвіт на свою адресу, час — через 5–10 хв, і запустіть ще раз уже **без** пробного режиму.
3. Біля кожного автозвіту в програмі видно «надіслано …» або помилку (`lastStatus`).

## 4. Обмеження й застереження
- **Не перевірено на реальній пошті** — скрипт написано й перевірено тестами логіки (періоди, час, групування, суми), але справжнє надсилання вперше відбудеться під час вашої перевірки (див. розділ 3).
- GitHub **вимикає розклад у репозиторіях без активності 60 днів**: якщо програма довго без змін у коді, зайдіть в Actions і ввімкніть workflow знову.
- Щоразу скрипт читає лише записи за потрібний період (не всю базу); якщо немає автозвітів, що настав їх час, нічого не читає, крім списку автозвітів.
- Gmail дозволяє до ~500 листів на добу — для цього більш ніж достатньо.
- Не надсилайте поштою звіти з персональними даними пацієнтів.
- Сервісний акаунт обходить правила бази — зберігайте ключ лише в Secrets.

## 5. Файли
`autoreport/lib.mjs` — логіка (періоди, час, таблиці), `autoreport/test.mjs` — тести (`npm test`), `autoreport/send.mjs` — читання бази й надсилання, `.github/workflows/autoreport.yml` — розклад. Правила Firestore для `auto_reports`: читає/пише лише Керівник/Адмін з правом «Автозвіт».
