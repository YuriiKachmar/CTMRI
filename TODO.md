# Відкриті питання та невиконане (оновлювати після кожного етапу)

## Журнал / форма візиту
- Лікар не може відкрити візит, щоб поставити відмітку «описано» (залежить від матриці «Доступи»; питання «Редагування для лікаря»).
- Журнал без віртуалізації списку: місяць рендериться цілим (оптимізувати, якщо буде повільно).
- Календар «Обрати день»: не позначено дні, де є записи (потрібен окремий запит).
- Колонка «Оплата» у журналі — ✓/✕ як у макеті журналу; уточнити в користувача, чи залишати (у формі візиту від ✓/✕ відмовились).
- Лічильники `counters/sequential` і `counters/monthly` стартують з 1; якщо потрібно продовжити паперову нумерацію — вписати значення вручну.
- Тимчасові константи: HAS_MONEY_RIGHT, FACILITY_TRACKS_PAYMENT (з матриці «Доступи» і «Налаштувань»).
- Прийняті без макета рішення (підтвердити; лаборант: підпис «Лаборант», список лише лаборантів, «(я)» першим, обов'язковий вибір — за вказівкою користувача): «Опис» = відмітка; форма оплати без значення за замовчуванням; скерування обов'язкове.

## Далі за планом
- Вкладка «Пацієнти» (пошук, картки, історія візитів).
- Матриця «Доступи» + права в картці працівника; тимчасові перевірки ролей замінити.
- Налаштування, Календар чергувань, Звіти.
- `visitsInPeriod()` досі повертає 0 — підключити до реальних візитів (виключення партнерства/змін; пошук працівників за id і `legacyId`).
- Звузити правила Firestore за ролями (нагадувати republish при змінах `firestore.rules`).
- Логотип у Firestore, пункти з ПАМЯТКИ, мобільна версія.
- Наприкінці: перерахунок обсягів даних і вибір платформи (безкоштовні ресурси); оновлення README.
